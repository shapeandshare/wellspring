# evolutionary-pipeline-optimization-roadmap - Work Plan

## TL;DR (For humans)

**What you'll get:** The engineering work needed to (1) make Heretic's existing automatic abliteration search visible in MLflow, and (2) build two brand-new automatic search loops that tune how the decensored model gets compressed into MLX and GGUF app formats, scoring every attempt on the real, compressed file instead of guessing.

**Why this approach:** Heretic already runs its own automatic tuning step internally - we don't rebuild that, we just make it visible. The real gap is that nothing today checks whether a *compressed* model still answers correctly and still stays decensored, so that's where the new automatic tuning goes.

**What it will NOT do:** It will not change how Heretic itself decides to decensor a model. It will not mutate what datasets go into abliteration or calibration (only how many *samples* are drawn, and only where that actually has an effect - see Todo 6). It will not pick an MLflow server address for you - you supply that.

**Effort:** Large
**Risk:** Medium - the MLX-side perplexity approach depends on an unverified assumption about `mlx-lm`'s ability to load a vision-language checkpoint (the project's default model type), which is now gated behind a feasibility spike that actually tests a VLM fixture, not just a text one. Every other mechanism in this plan (Heretic's journal format, `llama-perplexity`'s output format, the Makefile's own destructive-overwrite/cleanup semantics) was independently verified against real source during two rounds of a dual high-accuracy review.
**Decisions to sanity-check:** (1) MLflow logging of Heretic's own run is done by reading its trial history file after the run finishes, not live during the run. (2) Every search trial's artifact is archived to a dedicated, separate archive root **outside** `MLX_OUT_DIR`/`GGUF_OUT_DIR` - both of those directories are destructively overwritten/cleaned on every `make convert-mlx`/`make quantize-gguf` call, so archiving *inside* them (an error caught in review round 2) would not survive the next trial. (3) Both new studies use two true objectives (perplexity, refusal-rate), never scalarized into one number, and use persistent on-disk Optuna storage so a study can resume after an interruption.

## Scope

### Must have
- New shared eval harness that computes perplexity and refusal-rate against an **actual exported, quantized** MLX or GGUF artifact (not the in-memory bf16 model Heretic itself evaluates).
- Post-hoc MLflow ingestion of Heretic's existing internal Optuna abliteration study (read its `JournalStorage` checkpoint file, log every trial as an MLflow run, with per-scorer metrics flattened to numeric values and deduplicated by a stable journal identity, not just trial number).
- A new, independent, **persistently-stored** Optuna study (driven by a new Python script + new `make optimize-mlx` target) that searches MLX export/quantization parameters (`Q_BITS`, `Q_GROUP_SIZE`, `QUANT_METHOD`, and, conditionally on `QUANT_METHOD=awq` AND `CALIBRATION=multimodal` only, `CALIB_SAMPLES`) against one fixed Heretic checkpoint, logging every trial to MLflow and archiving every trial's artifact - immediately, to a dedicated archive root outside `MLX_OUT_DIR` - before it would otherwise be overwritten.
- A new, independent, **persistently-stored** Optuna study (driven by a new Python script + new `make optimize-gguf` target) that searches GGUF export/quantization parameters (one quant type per trial from `GGUF_QUANTS`'s candidate set, plus `CALIB_TEXT_SAMPLES` as a sample-count tuning knob) against the same fixed checkpoint, logging every trial to MLflow and archiving every trial's artifact - immediately, to a dedicated archive root outside `GGUF_OUT_DIR` - before it would otherwise be deleted by the next trial's cleanup step.
- New direct dependencies: `mlflow`, `optuna~=4.7` (pinned to match `heretic-llm`'s own constraint), `mlx-lm` (for MLX-side perplexity - not installed today), `pytest` (dev dependency).
- `MLFLOW_TRACKING_URI` modeled as a required Makefile/env variable with no default.
- `build-llama-cpp`'s existing build-target list extended (additively) to also build `llama-perplexity` and `llama-cli`.
- README updates documenting the new `make` targets and variables.

### Must NOT have (guardrails, anti-slop, scope boundaries)
- No forking or patching Heretic's own source (`vendor/heretic/` stays a read-only reference clone; git-ignored and not built/imported by this project).
- No outer Optuna study that re-runs `make abliterate` per trial. Heretic's internal search is reused as-is.
- No corpus/dataset **identity** mutation (swapping which dataset `good-prompts`/`bad-prompts`/calibration prompts come from - the Makefile now exposes `GOOD_PROMPTS_DATASET`/`BAD_PROMPTS_DATASET`/etc. as pinned, overridable variables, which is useful groundwork for a *later* roadmap phase, but this plan does not vary them). **Varying sample *counts*** drawn from the existing fixed datasets, where that count actually has an effect (see Todo 6's conditional fix), is in scope as a tuning knob and is not the same thing as a dataset-identity mutation.
- No outer search over Heretic's own meta-settings and no joint MLX+GGUF multi-objective search - later-roadmap items.
- No live per-trial MLflow hook via Heretic's `Scorer` plugin API in this pass.
- No committing model/calibration/GGUF/MLX artifacts or any per-trial archive produced by Todos 6/7 (all git-ignored).
- No picking or hardcoding a concrete MLflow tracking server URI.
