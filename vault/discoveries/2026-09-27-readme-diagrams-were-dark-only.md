# README diagrams were dark-only; rgba fills escape hex colour mapping

Part of [[wellspring]]. Only the hero banner switched with the OS colour scheme.
`quantization.svg`, `pipeline.svg` and `metaflow.svg` have a baked-in dark
background, so light-mode readers saw three dark slabs.

## What was tested / observed

- `grep -c prefers-color-scheme docs/assets/*.svg` returned 0 for every file.
  Switching happens in the README's `<picture>` element, not inside the SVG, and
  only the hero had a `<picture>` element.
- The light variants were generated by mapping each dark hex colour to the
  light palette that `wellspring-hero-light.svg` already uses.
- Both colour schemes were rendered with
  `npx playwright screenshot --color-scheme=light|dark`.

## Finding

- The first light render of `pipeline-light.svg` had murky grey-green and
  grey-blue export panels. Those two panels used `fill="rgba(5,46,22,0.35)"`
  and `fill="rgba(30,58,95,0.35)"`, which a `#rrggbb` regex never matches.
  After those were fixed by hand, a grep for leftover `rgba(` found only one,
  a harmless 8%-opacity green in `metaflow`.
- The automated check ("no unmapped hex colours left") passed while this
  defect was on screen. This is another case for AGENTS.md §4: render and look.

## Relevance

- Any new dark-background diagram needs a `-light.svg` sibling and a
  `<picture>` embed (`docs/DESIGN.md` now says so).
- When recolouring SVGs by script, also grep for `rgba(`, `rgb(`, 3-digit hex,
  and named colours.
- The light files are hand-maintained siblings, not generated output. Edit
  both files when a diagram changes.
