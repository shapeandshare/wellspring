Asked for richer, better-spaced instructions and a separate handoff per team.

## What was built

- **`docs/RED.md`** — build → train → gate → wordlist → handover, with a contents list, what-each-knob
  tables, a hand-over checklist and an explicit do-not-give list, plus timings and a symptom table.
- **`docs/BLUE.md`** — the situation, what you were given, setup, the two measurements, a verdict
  table, what to report, a stuck-symptom table and deeper ideas. **No answers anywhere.**
- **`docs/FACILITATOR.md`** — session shape with wall-clock, prep, handover checklist, what to say
  verbatim at four moments, known failure modes, and difficulty dials including two that are traps.
- **`README.md`** — now opens with a router table (facilitator / Red / Blue / maintainer), a
  "this file contains spoilers" panel, and the four commands that keep the exercise safe.
- **`handover/HANDOFF.md`**, generated by `scripts/handover.sh` from the recipe stamps: which base the
  models came from, the upstream repo to fetch, the parity statement, what else Blue needs, and the
  two commands in order.
- **`preflight.py --blue`** — checks what the auditing side needs and verifies method parity across
  the stamps; skips the Red-only dataset/answer-key/handover checks.

## Two things this caught

1. **Blue's draft leaked the answer.** It quoted real captured output — `BACKDOORED: B, E`, and a
   ranking starting `A, E`. In the documented default lineup those *are* the sleepers, so the
   "illustrative" example was the answer key. Example blocks now use placeholder names (`P`, `Q`, `R`)
   and say so. Writing the document as a genuinely separate artifact, rather than a filtered view of
   the README, is what surfaced it.

2. **`preflight` reported a layer band that did not exist.** It computed the dead `--num-layers`
   window from the default 16 even when the cohort had been trained with `-1`. Noise for Red,
   misleading for Blue. It now prefers the value in the models' own stamps and names its source.

## Review pass — errors found in the new material

Reading the generated `HANDOFF.md` as Blue would actually use it found that **its commands worked
from neither plausible working directory**:

- from inside `handover/`, where the note lives, `python src/weight_diff.py` does not exist;
- from the repo root, `--variants ./*/` matches `data/ docs/ env/ scripts/ src/ vault/` — it would
  have tried to diff the repository against itself.

The note now states the assumed working directory explicitly and uses the staged directory's real
name (`handover/*/`, `--models handover`), with a `--blue` preflight as step 0. All three commands
were then run verbatim against a live staged directory.

Three more, all in code written the same day:

- **Staging silently doubled disk use.** A 5-variant TinyLlama cohort is ~10 GB, so `make handover`
  needed another 10 GB that `preflight` never accounted for. Now it uses an APFS clone (`cp -Rc`,
  instant and copy-on-write) and falls back to a real copy only when cloning is unavailable — after
  checking there is room, because running out halfway leaves a partial directory that looks like a
  valid handover.
- **The space check measured the wrong filesystem** (`df -k .` rather than `DEST`'s volume), so
  `DEST=/other/volume` would have been checked against the current disk.
- **`train_variants.sh` still told Red to hand over `data/out/models/` by hand**, bypassing the
  staging gate that writes Blue's instructions and greps for the trigger — the same class of mistake
  as the earlier "Next: weight_diff" message. It now points at `make wordlist` and `make handover`.

## Second review pass — a broken mandatory gate

`make qa`, the step the constitution requires before handover, **had been broken for a day**, and so
had `make wordlist`. `reveal.py` defines `--answer-key` on the top-level parser, so argparse rejects
it after the subcommand — which is exactly where the `KEY=` passthrough put it.

Worse than the bug: it had been "verified" with `make -n`, which prints the recipe **without running
it**. That proved variable substitution worked and nothing else, while looking like a passing check.
`make test` missed it too, because `e2e_test.sh` calls `reveal.py qa` directly rather than through the
Makefile — the tested path and the documented path had diverged. It surfaced only when a timing
measurement showed `make qa` returning in **0 seconds**.

Fixed by accepting `--answer-key` on either side of the subcommand, correcting the Makefile, and then
running **every** target for real. Written up as
[[Discoveries/Dry-Run Verification Is Not Verification]].

Three more from the same pass:

- **`reveal.py wordlist` was predictable across sessions.** With the default `--seed 0` the shuffle
  was identical every run, so the trigger sat on the **same line number** for a given decoy count —
  anyone who had seen a previous session's file could skip to it. Now unseeded by default; `--seed`
  kept for tests. Decoys that overlap the trigger as substrings are also dropped, so Blue never gets
  two firing candidates for an artificial reason.
- **A stale `triggers.txt` silently breaks the next exercise** — it holds a trigger that no longer
  exists, so every model reports `NO_PAYLOAD`. `make clean-data` now deletes it and says why, and
  wordlists carry a `#` header explaining they are per-exercise. `probe.py` learned to skip `#`
  comments (and to fail loudly on an all-comment file) so annotated wordlists work.
- **`make lint` had never passed** — 12 findings on a clean checkout, which trains people to ignore
  it. Two were real (unused import, `f.write` in a loop) and are fixed; the deliberate grouped-import
  style now carries a local `# noqa` that explains itself; `make format-check` is labelled advisory
  because the repo is not ruff-formatted. `make lint` exits 0, so a finding means something. An
  attempt to do this via a `ruff.toml` with a broader rule set was reverted — it took findings from 12
  to 78.

Also corrected: `preflight --blue` told Blue they "need" disk for a lineup they already have, and the
README's `make test` runtime was stale (~29 min, measured 35m16s).

## Verification

- `make test`: **ALL CHECKS PASSED**, 35m16s, **32 assertions** — now including four for `preflight`
  (Red mode READY, `--blue` READY plus parity check, `--blue` silent about Red-only inputs, `--blue`
  rejects a bogus `--base`) — including two new ones: `HANDOFF.md`
  is written beside the models, and it does not contain the trigger.
- Blue's documented commands run verbatim against a real staged directory: the parity check, the
  `--blue` preflight, `weight_diff --variants ./handover/*/`, and
  `probe.py sweep --models ./handover --wordlist triggers.txt --json blue.json` (both sleepers found,
  decoys clean).
- Spoiler audit of `docs/BLUE.md` and `handover/HANDOFF.md` against the live answer key: neither
  contains the trigger, the payload text, or any claim about which variants are sleepers.
- All four documents: internal anchors resolve, file links resolve, every referenced
  `src/*.py`/`scripts/*.sh` exists, every `make` target named actually resolves.
- Static checks clean; ruff unchanged at 12 findings.

## Follow-up

Four documents now describe one system. Measured numbers stay in `README.md`;
`docs/FACILITATOR.md` carries reference results for calibration. If the pipeline changes,
that is two files to update, not one — worth watching for drift.
